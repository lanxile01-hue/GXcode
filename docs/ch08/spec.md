# GXCode Ch08 Spec — 项目记忆与会话管理

## 背景

当前 Agent 每次启动都是全新会话，不记得项目上下文和用户偏好。需三套机制实现分层记忆：项目指令（手写）、会话存档（JSONL 自动写）、自动笔记（LLM 自动生成）。

## 目标

- 项目指令三层加载（项目根 > .gxcode/ > ~/.gxcode/），@include 引用防环路
- 会话 JSONL 追加写，崩溃只丢最后一行，恢复时处理坏行/孤儿工具调用/token 超限/时间跨度
- 自动笔记四分类，LLM 异步更新+去重，索引控制在 200 行/25KB 内

## 功能需求

- **F1: 项目指令加载** — 三层路径各一份 Markdown，高优先级排前面拼接。支持 @include 引用其他文件，限嵌套深度（默认 3 层）、visited 集合防环路、拦截跳出项目目录的路径。
- **F2: 会话 JSONL 写入** — 每次用户消息和每条 LLM 响应追加写一行。不维护单独 meta 文件，会话列表直接扫 JSONL 推算 ID/标题/消息数。
- **F3: 会话恢复** — 坏行跳过（JSONDecodeError → 跳过该行）、工具调用没配上结果时截断、token 超限先压一次、隔太久（> 24h）插时间跨度提醒。
- **F4: 会话清理** — 30 天以上的过期会话定期清理。
- **F5: 自动笔记更新** — Agent Loop 自然停下后异步调 LLM，四分类（用户偏好/纠正反馈/项目知识/参考资料）更新笔记。去重由 LLM 判断：内容重复→合并，新内容→追加。
- **F6: 记忆注入** — 处理请求前，将记忆索引注入上下文，相当于 Agent 已「读过」。
- **F7: 笔记存储** — 用户级（~/.gxcode/memory/）和项目级（.gxcode/memory/）分开存。每条笔记一个带 frontmatter 的 Markdown。索引文件 <= 200 行 / 25KB。

## 非功能需求

- **N1:** JSONL 追加写 < 1ms（不含磁盘刷新）
- **N2:** 自动笔记 LLM 调用不阻塞用户交互
- **N3:** @include 路径解析不跳出 project_root
- **N4:** 会话 ID 格式 YYYYMMDD-HHMMSS-xxxx 防同秒冲突
- **N5:** 无新外部依赖（除 PyYAML 续用）

## 不做的事

- 向量数据库、RAG 检索、团队记忆同步
- 会话加密、多用户管理
- 笔记导出/导入

## 验收标准

- **AC1:** 三层指令按优先级拼接，@include 递归加载，环路检测生效
- **AC2:** 会话正常追加写 JSONL，崩溃后恢复只丢最后一行
- **AC3:** 恢复时坏行跳过、孤儿工具调用截断
- **AC4:** 30 天以上会话被清理
- **AC5:** Agent Loop 结束后自动笔记异步更新
- **AC6:** 笔记索引 <= 200 行 / 25KB
- **AC7:** 下次启动时记忆索引注入上下文
