# GXCode Ch04 Spec — 结构化 System Prompt

## 背景

Ch03 的 system prompt 是三行硬编码文本。不够结构化，无法灵活插新规则，也不区分稳定/变化内容。需要把全局指令拆成模块化构建块，让 GXCode 从"能干活"变成"干得好"。

## 目标

- 把系统提示拆成 7 个固定模块 + 3 个可选模块，按优先级拼装
- 区分稳定内容和变化内容：稳定指令走 system prompt（可缓存），环境信息走独立通道
- 在工具描述和全局指令中双重强化关键规则
- 用带特殊标签的消息注入运行时补充指令
- 会话级开关指令按轮次注入，控制注入频率
- 通过 API 缓存命中字段验证策略生效

## 功能需求

- **F1: 模块化 PromptBuilder** — 按优先级组装 10 个模块。固定：身份、系统约束、任务模式、动作执行、工具使用、语气风格、文本输出、环境信息。可选：自定义指令、已激活 Skill、长期记忆。模块间空行分隔。

- **F2: 稳定/变化内容分离** — 固定模块 + 工具描述走 system prompt（可缓存）。环境信息、对话历史、运行时补充指令走消息通道。

- **F3: 关键规则双重强化** — 工具描述和全局指令同时强调："编辑前先读"、"优先用专用工具"、"一次一个改动"。

- **F4: 带标签的运行时补充指令** — `/remind` 命令注入 `[SYSTEM_REMINDER]` 标签的 user 消息，不被当作用户输入回复。

- **F5: 会话级开关按轮次注入** — Plan Mode 首轮完整指令，每 3 轮简短重复，其余不注入。

- **F6: 缓存命中验证** — 解析 API 返回的 `cache_read_input_tokens` 等字段，日志记录。

## 非功能需求

- **N1: 缓存友好** — 相同配置产出的 system prompt 字节级稳定。
- **N2: 模块扩展性** — 新增模块只需实现 `() -> str` 函数，加入列表即可。
- **N3: token 开销可控** — Plan Mode 轮次注入不每轮发完整指令。
- **N4: 向后兼容** — Ch03 prompt 函数内部切换，外部调用不变。
- **N5: 性能** — build() < 1ms。
- **N6: 依赖最小化** — 无新外部依赖。

## 不做的事

- 项目指令文件加载
- 自动记忆/长期记忆存储
- 真实 MCP 接入
- 自动化评估
- 多语言 System Prompt

## 验收标准

- **AC1 (F1):** build(mode="act", tools=[...]) 返回含 7 个模块的完整 system prompt。
- **AC2 (F1):** 新增模块只需定义函数并加入列表。
- **AC3 (F2):** 连续两次 build() 返回相同字符串。环境信息不在 system prompt 中。
- **AC4 (F3):** edit_file 的 description 和全局指令同时包含"必须先 read_file"。
- **AC5 (F4):** `/remind 你在写 Python 代码` 后历史中出现 `[SYSTEM_REMINDER]` 消息。
- **AC6 (F5):** Plan Mode 首轮完整，每 3 轮简短提醒。
- **AC7 (F6):** 解析 API 响应的 cache_read_input_tokens 字段。
- **AC8 (N1):** 相同配置产物字节级一致。
- **AC9 (N4):** Ch03 调用方式不变。
