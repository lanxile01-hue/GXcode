## 修复：确认弹窗「点批准却执行拒绝」（Textual push_screen_wait 的 worker 限制）

现象：agent 写文件（write_file）弹确认框，用户点「批准执行」后仍显示「用户拒绝了工具调用」。

根因：`tui/app.py::_confirm_tool` 用 `await self.push_screen_wait(screen)`。Textual 8.2.8 的 `push_screen_wait` 内部走 `push_screen(wait_for_dismiss=True)`，要求必须在 worker 中运行；而 AgentLoop 跑在普通 `asyncio.create_task` 里 → 抛 `NoActiveWorker`，被 `loop.py::_request_confirmation` 的 `except Exception: return False` 静默吞掉 → 返回 False（拒绝）。弹窗其实已被压栈，所以用户能看到并点击，但结果没人接收。

修复：改用 `push_screen(screen, callback=...)` + `asyncio.Future` 等待结果，绕开 worker 限制。已用 .venv 实测复现（NoActiveWorker）并验证修复（点 OK 返回 True）。改后 py_compile 通过。

注：`loop.py::_request_confirmation` 的 `except Exception: return False` 是 fail-closed 安全兜底，但会掩盖此类异常，后续可考虑加日志。

对 GXCode TUI 做了整体视觉与交互升级，并用 `run_test` + `save_screenshot` 生成 SVG 截图逐项验证。

### 改动

### 踩坑（重要，Textual 8.2.8）
- **多个 `dock: bottom` 会重叠**：同一容器里两个 dock bottom 元素 region 完全重叠（都停在 y=最后一行）。改用 vertical 布局 + `height: 1fr` / 固定高度（不用 dock）解决。
- **Collapsible 子类覆盖 `compose` 会导致标题不渲染**：`Collapsible.compose` 里 yield `self._title` + `Contents()`。子类若只 yield 内容会丢掉标题。正确做法：内容作为 `super().__init__(content, title=...)` 的 children 传入，不要覆盖 compose。
- **`self._name` 与 Widget.name 冲突**：Widget 内部用 `_name` 存 name 属性，`super().__init__(name=None)` 会把它重置为 None。自定义属性改用 `_tool_name`。
- **Static 在 `__init__` 里调 `update()` 会渲染失败**（visual 为 None），改用 reactive + `render()`。

验证脚本模式：mock `ChatSession(provider=object())` + `ToolRegistry()`，`run_test` 里手动 `chat.add_*` 填充内容，`save_screenshot` 出 SVG，再用正则抽 `<text>` 按 y 坐标重建布局看效果。临时脚本已清理。
